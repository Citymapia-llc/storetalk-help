## Tables and QR codes

In the **Floor** tab of the dashboard you manage your tables. Add a table with a label
(e.g. `T4`), an optional zone (*Garden*, *Bar*), and a seat count. Each table gets its own
**QR code** — open it and print it (there's a Print button that lays the QR out for a
table tent or sticker).

When a guest scans the code, the menu opens **already bound to that table** — no login,
no typing a table number. They then choose to **pay now** or **run a tab** and settle at the
end; several rounds settle as one bill. See [Dine-in, tabs & payments](/apps/restaurant-dine-in-tabs)
for the full flow, table hand-over safety, and the automatic cleanup timings.

The floor board shows every table at a glance: which are occupied, the current tab total,
and the live order queue. Staff can **Close tab** or **Clear table** to turn a table over, and a
table **frees automatically** once its last order is served.

## The Kitchen Display

The **Kitchen** tab is a live board of tickets. When an order is placed (and paid, if you
take payment up front), it fires to the kitchen as one ticket per **station** — grill, bar,
cold — each showing the items, chosen modifiers, and any notes ("no chilli").

Each ticket has a **timer** that ages from green to amber to red so nothing is forgotten,
and a bump button:

- **Start** — the ticket moves to *preparing*
- **Ready** — the item is plated / poured
- **Served** — the ticket clears; when every ticket for an order is served, the order is
  marked complete and (for dine-in) the table frees

**Recall** brings a ticket back if it was bumped too early. The board updates live across
every screen in the kitchen.

## Payment timing

In **Settings → Payments** you choose when payment is taken:

- **Pay before fire** — the kitchen starts only after the customer pays. This is how
  **takeaway, delivery and dine-in "pay now"** work.
- **Pay on collection / at counter** — the kitchen fires immediately and the bill is
  settled later.

Dine-in guests choose per order — pay now, or run a tab and settle at the end; see
[Dine-in, tabs & payments](/apps/restaurant-dine-in-tabs).

Payment itself is handled by your installed payment app (Stripe or Razorpay) — StoreTalk
never holds the money, and the customer pays in your currency. See
[Collecting payments](/payments/collect-payments) for setup.
